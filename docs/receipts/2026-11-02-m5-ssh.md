# M5 SSH — receipt (2026-11-02)

Milestone M5 adds allowlisted SSH sessions on top of the M4 commit (`2aa4c08`, tag `m4`). No paid APIs. Tests mock `ssh2` and do not open sockets.

## What changed

- `src/modules/ssh` now opens sessions with the `ssh2` package. The default client factory returns a real `ssh2` `Client`. Tests and the UI smoke inject an in-memory client instead.
- Hosts come from `~/.jewbot/hosts.json`, or from the path in `JEWBOT_SSH_HOSTS`. That file is the allowlist. A host entry may name a `privateKeyPath`, set `agent: true` (`SSH_AUTH_SOCK`), or set `askPassword: true`. Fields named `password`, `passphrase`, or `privateKey` are rejected, and the error does not include the value.
- An encrypted key, `askPassphrase: true`, or `askPassword: true` asks in the UI. The secret is held in memory until that host disconnects. It is not written to the hosts file, the known-host file, or the agent observation. If it shows up in command output, it is redacted.
- The first connection computes a `SHA256:` fingerprint of the server host key and waits for the owner to trust it. The fingerprint is stored in `~/.jewbot/known_hosts.json` (`JEWBOT_SSH_KNOWN_HOSTS` overrides the path, mode `0600`). A different fingerprint later asks again and does not replace the stored one unless the owner confirms.
- Sessions can be opened, listed, and closed. One session per host name. `exec` streams stdout and stderr. Kill cancels the running command. One command runs at a time on a session.
- Agent tools: `ssh_list_hosts`, `ssh_connect`, `ssh_exec`, `ssh_disconnect`. `ssh_exec` uses `checkShellCommand` and `consumeConfirmation`. A model-supplied `approved` or `executionId` does not run a destructive command. The owner confirm dialog mints the one-shot grant, same as the local terminal.
- The Electron window has an SSH panel (host list, connect, streamed output, kill, disconnect) plus host-key and passphrase dialogs. Agent `ssh_exec` also streams into the tool card.

## Known limits

- Remote commands use an SSH exec channel. There is no interactive PTY shell, SFTP, port forwarding, ProxyJump, or certificate authority.
- One session per configured host name, and one running command on that session.
- Jewbot's known-host file is its own JSON list. It does not read or write `~/.ssh/known_hosts`.
- The connect handshake waits up to 150 seconds so the fingerprint dialog has time to be answered. Dismissing the dialog, or letting it sit past the prompt timeout (110 seconds), refuses the connection.
- A passphrase or password is forgotten when the session disconnects. The next connect asks again.
- Output redaction only covers secrets this process is holding (passphrase, password, and the local private-key text). It is not a general secret scanner.
- Jewbot is not a sandbox. A confirmed remote command runs as that SSH user on that machine.
- The automated tests never open a real socket. A live Dell, Pi, or Mac still has to be tried by hand.

## What the owner must do to try a real host

1. Review this branch and merge it yourself when you want it. Do not treat the open PR as already approved.
2. After it is on `main`, tag that commit `m5` and push the tag. Do not tag the feature branch.
3. Install dependencies and start the app from a machine that can reach the host (`npm install && npm start`). Ollama is only needed for the agent, not for the SSH panel.
4. Create `~/.jewbot/hosts.json` (see the README example). Point `privateKeyPath` at a key file you already have. Do not put the key or a password in the JSON. For a key with a passphrase, set `"askPassphrase": true`. For ssh-agent, set `"agent": true` and make sure `SSH_AUTH_SOCK` is set in the environment that launches Jewbot.
5. Open the SSH panel, choose the host, and press Connect. If asked, enter the passphrase. Compare the shown `SHA256:` fingerprint with the host itself, for example `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` on that machine, before pressing Trust this key.
6. Run a harmless command first (`uname -a` or `echo jewbot`). Output should stream in the panel. Then try a destructive command such as `rm -rf` only to confirm the dialog appears, and press Cancel. Nothing should be sent until you press Run anyway.
7. To try the agent, ask it to list hosts, connect, and run that same harmless command. The first connection still waits on you for the fingerprint, and a destructive remote command still waits on the confirm dialog.
