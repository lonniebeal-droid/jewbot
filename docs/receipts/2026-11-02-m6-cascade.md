# M6 cascade — receipt (2026-11-02)

Milestone M6 adds a local task queue on top of the M5 branch (`4095cdf`, PR #6, not merged). No paid APIs. The agent tests mock `fetch`. Nothing in this milestone approves a destructive command, a file edit, or an SSH host key by itself.

## What changed

- `src/modules/cascade` now stores a queue at `<project>/.jewbot/cascade.json` (already gitignored). Each task has an id, title, prompt, status (`pending`, `running`, `done`, `blocked`, `failed`), an optional acceptance command, and a receipt path. A task left `running` by a crash is loaded back as `pending`. A queue file that is not valid JSON is left untouched.
- The runner sends the prompt through the existing agent loop (Ollama). When the agent finishes with `FINAL:` and there is no acceptance command, the task is `done` and the next `pending` task starts immediately.
- An acceptance command runs through the terminal module in the open project. Exit 0 is `done`. Any other exit, a timeout, or a kill is `failed`. A destructive acceptance command is not run: the task is `blocked` and the command was not granted an execution id.
- A step that needs a person is never self-approved. Destructive shell (local or `ssh_exec`), file-edit Accept, a secret-file read, an SSH host key, an SSH passphrase or password, and `ask_owner` mark the task `blocked` with a reason, write a receipt, and the runner moves to the next pending task. Model fields such as `approved`, `executionId`, or `confirmed` do not count.
- Other failures (model error, max steps, wall time, a refused paid host) mark the task `failed`, write a receipt, and also move on. Stop aborts the current task (`blocked`, "Stopped by owner") and does not start another. Pause lets the current task finish, then waits.
- Defaults are 8 steps and 3 minutes per task (`JEWBOT_CASCADE_MAX_STEPS`, `JEWBOT_CASCADE_MAX_MS`). Paid or non-local model hosts stay refused unless `JEWBOT_ALLOW_PAID=1`.
- Each finished task writes `.jewbot/receipts/<id>.md`: prompt, steps, acceptance output when it ran, and the result.
- The Electron window has a Cascade panel: queue, status, blocked or failed reason, Start, Pause, Stop, Add, Requeue, Remove. The chat Stop button also stops the cascade. The UI smoke drives that panel with a scripted executor so it does not need Ollama. Production runs the real agent.

## Known limits

- Cascade does not open the confirm dialog and wait. A task that needs Accept, a destructive grant, or a host-key check is blocked and skipped. Run that step from the chat, terminal, or SSH panel if you want it done. Requeue repeats the same prompt and will block again if the model asks for the same grant.
- One cascade task runs at a time. Chat and cascade share the project files, the local terminal, and the SSH sessions.
- The acceptance command is a shell command in the open project. It uses the same destructive-command gate as the terminal. Jewbot is not a sandbox.
- The step cap defaults to 8 and the wall clock to 3 minutes. A task that only needs more time fails closed instead of running on.
- The queue holds at most 100 tasks. Receipts redact known shell tokens; they are not a general secret scanner. Both the queue and the receipts live only on disk under `.jewbot/` and are gitignored.
- The automated tests never call a live Ollama or a paid API. A real cascade still needs `ollama serve` and a pulled local model.
